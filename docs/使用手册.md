# AgentFlow 使用手册

这份手册按"你真的打开界面点一遍"来写，每个按钮名、字段名都对应当前代码里的真实文案（截至 `28ea5a8`）。三种用法任选一种：

| 方式 | 怎么进 | 适合 |
| --- | --- | --- |
| 本地跑 | `uvicorn main:app --port 8000` → <http://localhost:8000> | 想改代码、跑测试、接自己的 Key |
| 桌面版 | 仓库根目录 `npm install && npm start` | 想当成一个 App 用，不用开终端 |
| 在线演示 | <http://47.101.60.110:8001>（需访问口令） | 给别人看、不想装环境；演示里已预置 3 条跑通过的示例 |

本地跑需要一个阿里云百炼 API Key（<https://bailian.console.aliyun.com/>），填进 `backend/.env` 的 `BAILIAN_API_KEY`。在线演示用服务端配置的 Key，你只管点。

## 1. 界面地图

左侧固定栏从上到下：

- **仪表盘** —— 四个统计卡（工作流、执行次数、今日执行、运行中）+ 最近工作流 + 最近执行。空状态里有「新建工作流」和「浏览模板」两个按钮。
- **工作流** —— 列表页。每条有 **打开 / 执行 / 导出 / 删除**，右上角有 **导入 JSON**（提示写得很清楚：导入会新建一份，不会覆盖同名工作流）。
- **编辑器** —— 干活的地方，三栏：左「节点类型」面板、中间画布、右「节点属性」面板。顶部一条工具栏：**AI 分解 · 撤销 · 恢复 · 检查 · 导出 · 运行 · 高级**。
- **模板中心** —— 8 张模板卡，点一张直接把它加载成画布上的工作流（还没存，改了才会落库）。
- **执行记录** —— 最多显示最近 50 条，每条可 **查看 / 停止（运行中）或 删除**，右上角 **清空已完成 (N)**。

右上角常驻 **新建工作流**；浏览器支持时还会出现 **安装应用**（PWA，可装成独立窗口）。

## 2. 第一次跑通（3 分钟）

1. 点 **模板中心** → 「文档摘要」→ 跳到编辑器，画布上已经有 开始 → 提取信息 → 生成摘要 → 结束。
2. 点中间那个「提取信息」节点 → 右侧属性面板把「提示词」改成你想问的，模型保持 `Qwen Plus（均衡）`，温度拖到 0.5。
3. 看右上角工具栏点 **检查**。通过会提示「检查通过，可以直接运行」，不通过会把问题逐条连起来告诉你（比如「节点「xxx」未填写提示词」）。
4. 点 **运行** → 弹窗「运行工作流」在「输入内容」里粘一段文本 → **开始运行**。占位符 `{{input}}` 引用的就是这段文字，可以留空。其实 **运行** 自己就会先做一遍检查再落库保存，赶时间可以直接点它。
5. 页面自动进入执行详情：节点按拓扑顺序亮起，每个节点一行日志带耗时（`（1234ms）`）和备注；跑完显示最终输出和「各节点输出」。
6. 中途想停就点 **停止运行**；这条记录之后在 **执行记录** 里随时能翻。

自动保存：编辑器里任何改动，停止输入约 400ms 后 PUT 整张图。保存失败会弹一次提示「自动保存失败：…，改动目前只在本地」，此时别关页面，继续改会自动重试。

## 3. 编辑器操作

- **加节点**：从左侧「节点类型」把条目拖到画布上，落在哪儿就在哪儿生成。新建节点会带上该类型的默认配置。
- **连线**：按住源节点右侧的**输出端口**，拖到目标节点的**输入端口**松手（拖的过程中有一条虚线跟着鼠标）。也可以松手后再点目标端口，两次点击同样连上；`Esc` 或在中途松手则取消这次连线。连自己、方向反了、重复连都会有明确提示。
- **条件分支的线**：条件节点右侧有 **两个** 端口（`是` / `否`），从哪个拖出去就走哪个分支，连线本身会染色区分。
- **删线**：直接点那条曲线 → 提示「已删除连线」。
- **删节点**：点节点选中 → 右侧属性面板最底下 **删除节点**。
- **动位置**：按住节点拖动；坐标也会随自动保存存下来。
- **改名**：属性面板的 **标题** 可改；**节点 ID** 和 **类型** 是灰色的、不可编辑（要改 ID 见第 9 节导入导出）。
- **撤销 / 恢复**：`Ctrl+Z` / `Ctrl+Y`（也支持 `Ctrl+Shift+Z`），或工具栏那两个图标。历史栈最深 50 步。输入框里打字时不劫持快捷键。
- **点空白处**：取消选中，属性面板回到「选择节点查看属性」。

## 4. 七类节点

| 类型 | 面板里叫什么 | 关键字段 | 干什么 |
| --- | --- | --- | --- |
| 开始 | 开始 | 无 | 唯一入口，把运行时输入透传成 `{{input}}` |
| AI 对话 | AI 对话 | 提示词、模型（Turbo/Plus/Max 三档）、温度 0~1 | 调百炼大模型 |
| 条件判断 | 条件判断 | 条件表达式 | 求值后走 `是` / `否` 两个出口 |
| HTTP 请求 | HTTP 请求 | 请求地址、请求方法（GET/POST/PUT/PATCH/DELETE）、请求头（JSON）、请求体、勾选「4xx / 5xx 视为执行失败」 | 调外部接口取数据；GET 时不显示请求体 |
| 文本处理 | 文本处理 | 处理方式（拼接文本 / 拆分为列表 / 查找替换）、文本片段（JSON 数组）、分隔符、查找 / 替换为 | 不动模型的结构化处理，`拆分为列表` 是给循环节点喂数据的 |
| 批量循环 | 批量循环 | 列表来源、分隔符、每项动作（调用大模型 / 仅收集原项）、最多处理条数、结果连接符、每项提示词、模型、温度 | 把列表逐项处理再聚合成一段 |
| 结束 | 结束 | 无 | 唯一出口，产出最终结果 |

分隔符类字段写 `\n` 表示换行（不是真的按回车）。

## 5. 变量引用

在任何文本配置框里都能写 `{{...}}`：

- `{{input}}` —— 这次运行时填进去的输入内容
- `{{节点ID}}` —— 那个节点的输出，例如 `{{llm_1}}`
- `{{item}}` / `{{index}}` —— 只在循环节点的「每项提示词」里有意义（当前条目、第几项，从 1 开始）

规则上有三件事值得知道：

1. **只替换一次**。所有占位符在一次扫描里完成替换，所以某个上游节点的输出里正好含 `{{input}}` 也不会被二次展开，结果不受字典顺序影响。
2. **找不到的变量原样留着**。写错 ID 时你能在日志里直接看到 `{{llm_5}}`，而不是被静默换成空。
3. 值是字典或列表时自动转成 JSON 文本（`ensure_ascii=False`，中文不会变 `\uXXXX`）。

## 6. 条件判断怎么写

支持 `==` `!=` `>` `>=` `<` `<=` `contains`，以及 `and` / `or`（`and` 优先于 `or`）。变量有两种等价写法：

```
llm_2 contains "80" or llm_2 contains "90"
'{{llm_1}}' contains "投诉"
split_1 > 3
```

左边直接写节点 ID 时会去上下文取值；用 `{{}}` 时先替换成文本再求值，这种写法记得加引号。数字和带小数点的字面量会按数值比较，不会被当成字符串。

**求值失败不会中断整条工作流**：表达式语法不对时记一条「表达式无法求值（…），走 false 分支」，继续跑 false 那条路 —— 日志里能看到原因。

没被选中的分支上的节点，在执行详情里显示为灰色「跳过」，而不是消失。

## 7. 批量循环

- 「列表来源」可写 `{{input}}`、某个上游节点 ID，或直接写一个 JSON 数组；不是 JSON 就按「分隔符」拆。
- 上游是「文本处理 → 拆分为列表」时，这里天然接得住（模板「批量条目处理」就是这么串的）。
- **并发 3** 项同时跑，最多 100 项（面板默认 20，超出会截断并在日志里给出项数）。
- 「每项动作 = 仅收集原项」时不调模型，只做拆分和拼接 —— 用它把长文本重排很省 Token。
- 某几项失败不会假装全成功：完成的条目照常聚合，日志里带上失败项数；全失败才报错。

## 8. 看执行结果

**执行详情**页有三块：

- 顶部状态 + 工作流名 + 时间
- **执行日志**：逐节点一行，状态标签是 完成 / 运行 / 错误 / 跳过 / 已停止，带耗时和备注（分支走向、项数都在这里）
- **各节点输出**：跑完后每个节点的原始输出，调试提示词时主要看这里

运行中打开页面也能看到已完成的部分 —— 状态是服务端快照推下来的，不是只靠当场 WebSocket。失败的运行同样留档，错误原因写在输出里。

## 9. 导入 / 导出 JSON

导出就是一张图的完整序列化：

```json
{
  "name": "示例工作流 - 智能问答",
  "description": "接收用户问题，通过 AI 生成回答",
  "nodes": [
    { "id": "start", "type": "start", "title": "开始", "x": 100, "y": 200, "config": {} },
    { "id": "llm_1", "type": "llm", "title": "AI 回答", "x": 320, "y": 200,
      "config": { "prompt": "…{{input}}", "model": "qwen-plus", "temperature": 0.7 } },
    { "id": "end", "type": "end", "title": "结束", "x": 540, "y": 200, "config": {} }
  ],
  "edges": [
    { "source": "start", "target": "llm_1" },
    { "source": "llm_1", "target": "end", "sourcePort": "output" }
  ]
}
```

- `sourcePort` 只在条件分支上需要（`"true"` / `"false"`），普通线写 `"output"` 或省略都行。
- 导入走 **工作流** 页的 **导入 JSON**，**永远是新建一份**，不覆盖同名的现有工作流。
- 导入时做结构校验（不要求流程已画完，草稿也能导）：节点 ID 必须是字母或下划线开头、只含字母数字下划线连字符、最长 64、不许重复；`type` 不能缺；连线两端必须指向存在的节点。**改节点 ID 只能靠这条路**（导出 → 改 JSON → 导入）。
- 执行前会做完整校验：缺「开始」/「结束」、「开始」多于一个、必填项空着（AI 对话的提示词、条件的表达式、HTTP 的地址）都会逐条列出来。

## 10. 让 AI 帮你搭图

编辑器工具栏 **AI 分解**：一句话描述任务 → 模型拆成子步骤 → **应用到编辑器**，直接变成画布上的节点和连线，然后再手工调。想看得更细，点 **高级** 打开同一个功能的完整版弹窗（自己写任务描述、看中间结果）。

## 11. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| AI 节点报 `404 Model not exist` | 你的端点没有这个公有模型名。在 `backend/.env` 里设 `BAILIAN_MODEL_TURBO` / `BAILIAN_MODEL` / `BAILIAN_MODEL_MAX`，把档位指到该端点实际提供的 id（演示服务器上就设了 `BAILIAN_MODEL_TURBO=qwen-flash`） |
| 报「模型没有返回内容，请重试或更换模型」 | 内容审核拦截或截断导致 choices 为空/`content` 为 null。改提示词或换档，别当成网络问题 |
| 一直显示「运行中」 | 执行是后台任务，关掉页面不影响它跑完；回 **执行记录** 刷新即可。想结束就点 **停止** |
| 「自动保存失败」 | 服务没起来或断网。改动仍在浏览器里，恢复后继续编辑会自动重试 |
| 在线演示提示次数用完 | 演示站有按 IP 的每小时限流和全站每日额度，第二天自动恢复；本地跑没这些限制 |
| 页面显示「这一页没有加载出来」 | 后端没响应（还没启动完、或者已经退出）。等它起来后点 **重试** 即可，不需要刷新整页 |
| 端口被占 | 换端口起：`uvicorn main:app --port 8001`，前端还是同一个页面 |

## 12. 15 分钟上手路线

按顺序做，做完就够你在别人面前演示了：

1. **模板跑通**（3 分钟）：文档摘要 → 运行 → 看「各节点输出」。
2. **改一条线**（2 分钟）：把「生成摘要」的提示词里 `{{llm_1}}` 手滑改成 `{{llm_9}}`，运行，从日志里认出没被替换的占位符 —— 这一眼比读十遍文档有用。
3. **模板「智能客服」**（3 分钟）：输入分别试一句「我要投诉」和一句「请问怎么开通」，两次执行对比条件节点日志里的 `分支 → true/false`，以及被跳过的分支显示成灰色。
4. **模板「批量条目处理」**（3 分钟）：输入粘 5 行任意文本，看循环节点日志里的项数和聚合结果。
5. **自己造一条**（4 分钟）：新建空白工作流 → 拖 开始 / HTTP 请求（地址填 `https://api.github.com/repos/cappercclove/agentflow`）/ AI 对话（提示词里用 `{{http_1}}`）/ 结束 → 连线 → 检查 → 运行。

## 13. 想改代码的话

```bash
# 起服务（改完 .py 要重启，前端静态文件刷新即可）
cd backend && uvicorn main:app --reload --port 8000

# 跑测试：必须站在 backend/ 里，pytest.ini 在那
cd backend && python -m pytest -q          # 154 个用例，不需要 Key、不联网
cd backend && python -m pytest tests/test_engine.py -q   # 只跑引擎

# 桌面版
npm start
```
